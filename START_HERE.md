# Team TwinPulse - GlucoTwin submission package

Everything required locally for the non-video submission is included. Public upload and link checks are separate actions. This ZIP is not itself a submitted GitHub repository or video.

## Upload to GitHub

1. Extract this ZIP.
2. Open its `TwinPulse_VIT_Bhopal_VIT_Vellore` folder.
3. Upload **the contents of that folder** to https://github.com/rimzim9934/glucotwin-digital-twin. Keep `README.md`, `LICENSE`, `app.py`, `docs/`, `reports/`, `output/` and the other source files at the repository root. Do not upload only the ZIP.
4. Include `.gitignore` and `.streamlit/config.toml`. Some file pickers hide files beginning with a dot.
5. Open the public repository while signed out. Follow the README links to the architecture, report and presentation, and check that each file downloads without permission prompts.
6. Record/upload the unlisted YouTube video. Replace the pending Demo video notice in README.md with its actual watch URL, then check it signed out.
7. Rimzim Kumari, team leader, enters the public repository URL and completes the organizer form. Save the receipt.

## Required deliverables

- `README.md`: team, college, title, problem, healthcare use case, stack, model details, results, licensing and links.
- `output/pdf/GlucoTwin_Reliability_Architecture.pdf`: architecture diagram.
- `output/presentation/GlucoTwin_TwinPulse_Reliability_Edition.pptx`: editable presentation covering project and results.
- `output/pdf/GlucoTwin_Project_Reliability_Edition.pdf`: current project report.
- `docs/VIDEO_HANDOFF.md`: current recording plan and verified result numbers. The video itself remains the team's task.
- `docs/SUBMISSION_CHECKLIST.md`: complete item-by-item checklist and access checks.
- Source files, dependencies, tests, frozen experiment evidence, corrected warning audit, reliability benchmark and example forecast receipt.

## Run the project

Follow README.md. Raw research data and binary models are deliberately excluded from public upload. The official numeric-data downloader, preprocessing and training commands regenerate local runtime artifacts. The pinned source data and code/data licenses are documented. No hardware or cloud credentials are needed for recorded-data replay.
